# Principle 4: Dynamic Specialization & Bounded Execution

## Detailed Specification & Rationale

* **Core Law**: Solve tasks with no wasted agent steps, under explicit step budgets (`max_turns`) and token ceilings — *no wasted steps*, never *the fewest steps regardless of answer quality*; delegate to ephemeral sub-agents with clean context isolation. Background knowledge and skill enrichment (P7, P9) operates strictly off the critical response path.
* **Strict Rule**:
  - **Explicit Turn & Token Budgets (falsifiable)**:
    - **"Turn" names two different things, and only one of them is bounded here.** An **interaction turn** is one externally-initiated request — a person's message, an A2A task, a CLI prompt. An **agent step** is one model invocation and its tool round taken *inside* one such request, without returning to the caller. The earlier wording said "per interaction turn" and was implemented against the first, which bounded conversation length; that is not what this law is for (see §Why: *unbounded loops*, *unprovable termination*). Resolved by `2026-09-05-001`.
    - Every agent execution must operate within explicit, measurable step limits (`AgentConfig.max_turns`) and session token budget ceilings (governed under [P5](p5-llm-token-management.md)).
    - **Agent steps are expected, not rationed.** Answering a request is a given; the agent should take as many agent steps as the task warrants — invoking tools and **feeding their results back to the model** — to reach the best answer it can. `max_turns` is a runaway guard, not a target to minimise toward. An implementation that stops after a single model invocation, or that executes tools and returns without letting the model see their output, fails this law rather than satisfying it: it produces a worse answer and bounds nothing, since one step cannot spin.
    - **`max_turns` bounds agent steps within a single run.** A step counter increments monotonically for each agent step taken without returning to the caller, and is reset when a new externally-initiated request begins. If it reaches `max_turns`, or the session token budget is exhausted, execution must terminate immediately with an explicit error or partial result envelope — silent or unbounded spinning is strictly forbidden.
    - **A sequence of interaction turns is not bounded by `max_turns`.** Each is gated by the party that issued it, so termination is already provable and no spinning is possible. An agent that refuses an interaction turn because a count of previous interaction turns was reached violates this law rather than enforcing it.
    - **`max_turns` is not a token ceiling and must not be relied on as one.** Token use tracks model invocations and context size, not counts: a few large-context steps can consume more tokens than many small ones. Token use is bounded by the session token ceilings named above, which accumulate across interaction turns and are not reset by them ([P5](p5-llm-token-management.md)).
    - **Falsifiable in both directions**: a conversation of `max_turns + 1` interaction turns must complete; a run of `max_turns + 1` agent steps must terminate with an explicit envelope.
  - **Ephemeral Sub-Agent Delegation & Bounded Recursion**:
    - Complex tasks must be delegated to ephemeral specialized sub-agents with strictly bounded recursion depth (`max_subagent_depth = 2` default, enforced via the narrowing invariant) and isolated context windows, preventing parent context pollution.
    - Sub-agents are created on demand for discrete sub-goals and terminated upon completion. Their conversation histories remain encapsulated in their own isolated sessions.
  - **Off-Critical-Path Background Enrichment**:
    - Knowledge induction (P7 ontology evolution) and skill synthesis (P9 dynamic skills) execute strictly off the critical response path as asynchronous background jobs.
    - User response delivery and task completion must never be blocked or delayed by post-execution learning, ontology graph updates, or skill extraction.
* **Why**: Monolithic agents with unbounded loops and massive context windows suffer from high latency, prompt dilution, runaway token costs, and unprovable termination. Replacing unfalsifiable aspirations ("as quickly as possible") with verifiable turn limits and token budgets makes agent execution deterministically bounded. Ephemeral sub-agents provide clean parallelism and targeted reasoning, while decoupling background enrichment guarantees prompt response turnaround without compromising system self-evolution.
