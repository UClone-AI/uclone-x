# Principle 3: Single-Machine Acceleration & Pluggable Sandboxing

## Detailed Specification & Rationale

* **Core Law**: The Agent Kernel must achieve maximum throughput and minimal latency in-process with zero external broker dependencies, while multi-process server deployments scale horizontally through stateless `cluster_protocols.py` adapters, with pluggable sandboxing across all tracks.
* **Strict Rule**:
  - **Zero-Broker Kernel SDK & Embedded Path**: Inside the Agent Kernel (`uclone_x.engine`, `uclone_x.agent`, `compose_agent`, `ucx run`, `ucx acp serve`, and embedded desktop adapters), event dispatch and sub-agent delegation execute strictly in-memory (in-process async queue / zero-copy coroutine dispatch) and must never require or import an out-of-process message broker. External brokers and stores (Kafka, Valkey, PostgreSQL, Centrifugo) live strictly behind `adapters/cluster/` and `shells/` for the declarative multi-process platform (`ucx up`), so `pip install uclone-x` and in-process agent execution run at full capability when Docker and cluster brokers are absent.
  - **Selective Sandboxing**: Tool execution defaults to filesystem isolation (`isolation_level="workspace"`). Stronger isolation (`container`, `wasm`) is available by user configuration for untrusted workloads. Direct host execution (`none`) remains supported but is an **explicit opt-in** for trusted local work — it must never be reached by defaulting.
  - **A weaker level is never selected implicitly**: an artifact — a synthesized skill, a remote A2A task, an MCP tool — may *request* an isolation level, and the effective level is the **stronger of the request and the runtime's floor**. An artifact may ask for more isolation than the floor requires; it can never obtain less.
    > Stated as a comparison rather than as "clamping", because clamping has no fixed direction: the same operation reads as clamping *down* if you measure privilege and *up* if you measure isolation, and that ambiguity is how an escalation gets written by someone who read the sentence the other way.
  - **Isolation is not the credential boundary**: `workspace` bounds writes; it does not scrub the environment or restrict egress. Credential protection is a separate obligation and must not be presented as satisfied by the isolation level. See [`docs/public/security.md`](../../public/security.md).
* **Why**: Embedders and CLI users need instant in-process startup without running infrastructure containers, while full-stack server operators need horizontal stateless durability without maintaining a divergent server codebase. Separating the **in-process Kernel law** (zero external broker inside `engine/` and `agent/`) from the **stateless server shell** (`ucx up` over `cluster_protocols.py`) keeps both guarantees falsifiable by inspection: any Kernel or `pip install uclone-x` SDK code path that requires an external broker violates this principle, and any server feature that bypasses `cluster_protocols.py` to reintroduce sticky in-memory server state violates stateless parity.
* **Numeric targets live elsewhere**: This principle does not fix a latency number. Concrete, revisable performance budgets for dispatch overhead and for agent turn latency are defined in [`docs/public/performance.md`](../../public/performance.md), which principles reference by name rather than encode. A tuning constant is not law; only the zero-broker *requirement* above is.
